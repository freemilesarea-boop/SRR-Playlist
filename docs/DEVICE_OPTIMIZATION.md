# 기기별 최적화 — 안드로이드 폰 · 아이폰 · 안드로이드 태블릿 · 아이패드

앱 하나가 네 종류의 기기에서 돈다. 그런데 코드에는 그 넷을 구분하는 수단이
**CSS 브레이크포인트밖에 없었다.** JS 어디에도 "지금 폰인가 태블릿인가" 를 묻는
곳이 없었고, 그래서 화면 크기와 상관없이 같은 판단을 내렸다.

가장 눈에 띄던 증상: **매장 계정으로 폰에서 앱을 열면 전체화면 매장 플레이어만 떴다.**
검색도 홈도 못 보고, 매번 "나가기" 를 눌러야 했다. 그 규칙은 원래 카운터에 세워두는
태블릿을 위한 것이었는데 폰까지 같이 걸린 것이다.

## 판정 기준 — 짧은 변 600px

`src/lib/deviceClass.ts`

```ts
export const TABLET_MIN_SIDE = 600;
export function isTabletSize(width: number, height: number): boolean {
  return Math.min(width, height) >= TABLET_MIN_SIDE;
}
```

`innerWidth` 만 보면 **폰을 눕혔을 때 태블릿으로 잘못 읽는다**(아이폰 16 Pro Max 가로는
956px 다). 그래서 짧은 변을 본다 — 돌려도 기기 종류는 안 바뀐다.
600 은 안드로이드의 `sw600dp` 관례다.

| 기기 | 크기 | 짧은 변 | 판정 |
|---|---|---|---|
| 아이폰 SE | 375×667 | 375 | 폰 |
| 갤럭시 S24 Ultra | 412×915 | 412 | 폰 |
| 아이폰 16 Pro Max | 440×956 | 440 | 폰 |
| 아이패드 미니 | 744×1133 | 744 | 태블릿 |
| 갤럭시 탭 S9 | 753×1205 | 753 | 태블릿 |
| 아이패드 프로 13 | 1024×1366 | 1024 | 태블릿 |
| 매장 태블릿(가로) | 1280×800 | 800 | 태블릿 |

CSS 도 같은 기준을 쓴다 — `@media (min-width: 700px) and (min-height: 600px)`.
가로·세로를 함께 보는 이유가 위와 같다. 예전에는 `(min-width: 1024px)` 하나였는데,
그러면 **세워 든 아이패드가 전부 폰 레이아웃을 받았다**(미니 744, 10.9인치 820,
프로 11인치 834). 글자 확대(`font-size: 17px`)만 1024px 에 남겼다 — 그건
"벽에 세워두고 한 걸음 떨어져 보는" 매장 태블릿 이야기지, 손에 드는 아이패드가 아니다.

회전은 `useIsTablet` 이 `resize` 로 다시 계산한다. 아이패드를 돌렸을 때 하단탭 구성이
그대로 남으면 안 되기 때문이다.

## 폰과 태블릿이 달라지는 곳

| | 폰 | 태블릿 |
|---|---|---|
| 앱 켤 때 매장 계정 | 홈 (가로채지 않음) | `/business` 또는 `/business/player` |
| 브랜드 묶인 기기 | 홈 | 브랜드 플레이어 |
| 하단탭(매장 계정) | 홈·매장·검색·보관함·더보기 | 매장·검색·보관함·내 정보·더보기 |
| 매장 대시보드 | 세로 한 줄 | 2단 (1.5 : 1) |
| 내 정보 | 세로 한 줄 | 2단 흐름 |

폰에서도 매장은 하단탭에 **그대로 남는다** — 접근성을 잃지 않으면서 앱처럼 쓸 수 있다.

실제 렌더로 확인한 결과(매장 계정 하단탭 첫 칸):

```
Android폰(412×915)      홈·매장·검색·보관함·더보기
Android폰 가로(915×412)  홈·매장·검색·보관함·더보기   ← 눕혀도 폰
iPad mini(744×1133)     매장·검색·보관함·내 정보·더보기
매장태블릿(1280×800)     매장·검색·보관함·내 정보·더보기
```

## 안전영역(노치 · Dynamic Island · 홈 인디케이터)

`.pl-safe` 같은 클래스가 `@layer base` 에 있었다. base 는 Tailwind utilities 보다
먼저 깔리므로, `px-3 pl-safe` 처럼 같이 쓰면 **px-3 이 이겨서 안전영역이 통째로
무시됐다.** 미니 플레이어 · 토스트 · 테마 토글 바 · 브랜드 플레이어 오류 화면 네 곳이
그랬다 — 아이폰을 눕히면 노치에 물리는 자리들이다.

utilities 레이어로 올리고(그러면 이번엔 반대로 안전영역이 여백을 먹으므로),
여백이 함께 필요한 네 곳은 `max()` 로 바꿨다:

```
pl-[max(0.75rem,env(safe-area-inset-left))]
```

`src/lib/safeArea.test.ts` 가 같은 방향에 숫자 padding 과 `*-safe` 를 함께 쓰는 것을
막는다. 어느 쪽이 이기든 고장이기 때문이다.

`index.html` 의 `viewport-fit=cover` 도 확인했다 — 이게 없으면 iOS 에서
`env(safe-area-inset-*)` 이 전부 0 이라 `pb-safe` 가 통째로 무의미해진다.

## 화면 높이 — 100vh → dvh

`h-screen` / `min-h-screen` / `100vh` 13곳을 `dvh` 로 바꿨다. 모바일 브라우저에서
`100vh` 는 주소창을 포함한 높이라, 로그인 화면 하단 버튼이 주소창 밑으로 숨었다.

## 브라우저 크롬 색

아이폰·아이패드는 지금 **PWA 로만** 돈다(Capacitor 프로젝트는 안드로이드만 있다).
네이티브 StatusBar 플러그인이 없으니 상태바/툴바 색을 정하는 건 `theme-color`
메타 태그 하나뿐인데, `#0a0a0a` 로 고정이었다 — 라이트 테마로 써도 거기만 새까맸다.

`applyThemeAttributes()` 가 테마를 바꿀 때마다 `--color-bg` 를 읽어 메타 태그를 갱신한다.
시간대(timeslot) 테마까지 자동으로 따라간다.

## 손가락 크기

체크박스·라디오는 브라우저 기본이 13×13 이다. 20×20 으로 키우고 `accent-color` 를
테마 색으로 맞췄다. 웹에도 적용한다 — 아이폰·아이패드가 PWA 로 도는 이상
`.native-shell` 안에 넣으면 정작 손가락으로 쓰는 기기가 빠진다.

그 밖에 22개 조작부를 44px 로 키웠다(매장 ON/OFF 토글, 플레이어 나가기, 문의하기 칩,
새로고침, 운영 콘솔 체크리스트, 결제 결과 화면 링크 등).

`.native-shell .app-footer-space` 의 아래 여백도 9rem → 11rem 으로 올렸다.
9rem 은 하단탭만 계산한 값이라, 플레이어 바(bottom 5.25rem + 높이 4.5rem)가 떠 있으면
아이폰 SE 같은 짧은 화면에서 맨 아래 한 줄이 플레이어 밑에 깔렸다.

## 점검 방법

6가지 크기 × 67개 화면 = **402회** 실제 렌더. 역할별(개인·매장·아티스트·본사·관리자)
세션을 넣고, Supabase 요청은 전부 가로채 운영 DB 에는 닿지 않는다.

각 화면에서 보는 것: JS 예외 · 빈 화면 · 가로 넘침 · 앱인데 웹 사이드바가 보이는지 ·
하단탭이 없는지 · 하단탭에 가려 못 누르는 조작부 · 손가락으로 누르기 어려운 크기.

### 결과

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| JS 예외 · 빈 화면 · 가로 넘침 | 0 | **0** |
| 앱인데 사이드바 노출 · 하단탭 없음 | 0 | **0** |
| 하단탭에 가려 못 누름 | 1 (아이폰 SE, `/business`) | **0** |
| 누르기 어려운 크기 | 132건 | **42건** |

여섯 크기 전부에서 레이아웃이 깨지는 곳은 없었다. 크기가 달라서 생긴 문제는
하단탭에 가리던 아이폰 SE 한 건뿐이었고, 나머지는 전부 기기와 무관하게 같이 나오던
것이다(= 여섯 크기에서 똑같이 잡혔다).

남은 42건은 7개 × 6크기이고, 두 종류다:

- **약관·개인정보·고객센터의 본문 속 메일 링크 3개** — 문단 안에 흐르는 글자 링크다.
  44px 로 키우면 문단 줄간격이 무너진다. 같은 화면 안에 버튼형 문의 동선이 따로 있다.
- **체크박스 4개(20×20)** — 기본 13px 에서 키운 값이다. 검사기의 기준(높이 32px)은
  버튼 기준이라 체크박스는 계속 잡힌다. 44px 체크박스는 오히려 고장으로 보인다.
