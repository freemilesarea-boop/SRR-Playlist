# 앱 화면 렌더 점검 — 찾은 것과 고친 것

앱 크기(`.native-shell`)에서 **67개 화면 × 2가지 크기 = 134회**를 실제로 그려서 점검했다.
폰 390×844, 태블릿 1280×800. 67개 = 페이지 43 + 관리자 탭 21 + 파라미터 경로 몇 개.
로그인이 필요한 화면은 역할별(개인·매장·아티스트·본사·관리자) 세션을 넣어 열었다.

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| JS 예외 | 1개 화면 | **0** |
| 가로 넘침 | 1개 화면 | **0** |
| 하단탭에 가려 못 누름 | 28건 | **0** (전부 오탐 — 아래 참고) |
| 누르기 어려운 크기 | 100건 / 50개 화면 | **44건 / 22개 화면** |

## 고친 것

### 1. JS 예외 — 매장 모니터링 패널이 통째로 죽던 것

`admin_list_enterprise_regions` RPC 가 null 을 돌려주면 `'data' in null` 에서 터졌다.
바로 윗줄은 같은 위험을 `Array.isArray` 로 막고 있는데 아랫줄만 빠져 있었다.

- `src/lib/api/enterpriseRegionsApi.ts` — null 을 받아도 항상 약속한 모양을 돌려주도록.
  타입은 `EnterpriseRegionListResponse` 를 약속해놓고 null 을 그대로 캐스팅하고 있었다.
- `src/components/admin/StoreMonitoringPanel.tsx` — 호출부도 방어.

### 2. 가로 넘침 — 관리자 정산 V2, 폰에서 147px

공용 컴포넌트의 액션 슬롯이 `shrink-0` 라서, 버튼이 몇 개만 늘어도 `max-content` 폭을
그대로 쓰고 화면 밖으로 나갔다. `max-w-full` 을 더해 안쪽 `flex-wrap` 이 동작하게 했다.

- `src/components/admin/ui/AdminSection.tsx`, `AdminCard.tsx` (관리자 전역에 적용)

### 3. 누르기 어려운 크기 — 100건 → 44건

앱에는 마우스가 없다. 손가락 접촉면이 9mm 안팎이라 높이 17~29px 짜리는 옆 것을 같이 누른다.
권장치는 44px(Apple HIG / Material).

두 가지 방식을 썼다. **웹(마우스)에는 적용되지 않으므로 데스크톱 밀도는 그대로다.**

- `.app-tap` — 개별 조작부에 붙인다 (min-height 44px).
  관리자 네비 칩 4곳, 빵부스러기, `/search` 추천 칩, `/sales-partners` 업종 칩,
  문서 화면·둘러보기 화면의 "홈으로" 링크.
- `.app-tap-area` — 조작부가 수십 개 컴포넌트에 흩어진 화면에 한 번만 붙인다 (min-height 40px).
  관리자 전체, 내 정보, 본사 화면 4개.

44px 가 아니라 40px 로 잡은 이유는, 표가 빽빽한 관리자 화면에서 행 높이가 한 번에 2.5배가
되면 오히려 한 화면에 아무것도 안 들어오기 때문이다.

## 오탐이었던 것 — "하단탭에 가려 못 누름" 28건

**전부 오탐이었다.** 검사기가 두 가지를 안 봤다:

1. **스크롤 0 에서만 측정했다.** 스크롤하면 빠져나오는 것까지 "가려짐" 으로 셌다.
2. **z-index 를 안 봤다.** 매장 플레이어는 `z-[90]` 전체화면이라 `z-30` 하단탭보다 위에 있다.
   겹쳐 보여도 실제로는 눌린다.

끝까지 스크롤한 뒤 `elementFromPoint` 로 그 점을 실제로 때려보도록 검사기를 고쳤다.
고친 검사기로 다시 돌리니 28건 → 0건.

## 남은 44건

한 화면에 1~2개씩 흩어져 있고, 성격이 제각각이라 일괄로 못 고친다.

| 화면 | 남은 것 |
|---|---|
| `/ops` 운영 콘솔 | 7개 — 소비자 셸 밖의 별도 레이아웃이라 위 규칙이 안 닿는다 |
| `/business` | 5개 — `OFF(44×19)` 등 스케줄러 토글 |
| `/library` | 2개 — 빈 상태의 "차트에서 둘러보기" |
| 문서 화면들 | 본문 속 메일 링크 — 산문 안의 인라인 링크라 키우면 줄 간격이 깨진다 |
| `/profile` | 체크박스 1개 (13×13) — 라벨까지 누르게 하는 편이 낫다 |

## 이 점검이 볼 수 있는 것 / 없는 것

**본 것** — 가로 넘침, 하단탭 가림(실제 클릭 판정), 조작부 크기, JS 예외, 빈 화면, 사이드바 노출.

**못 본 것** — 색 대비, 실제 데이터가 많을 때의 밀도, 스크롤·제스처 느낌, 애니메이션,
실제 기기의 폰트 렌더링. 이건 사람이 기기에서 봐야 한다.

서버 응답은 가짜다. 운영 DB 에 닿지 않도록 가짜 호스트(`stub.supabase.co`)로 빌드하고
모든 요청을 가로챘다. 따라서 **데이터가 채워진 상태의 레이아웃은 검증되지 않았다.** 빈 상태 기준이다.

> 가짜 응답을 만들 때 주의할 것: 없는 데이터를 빈 객체 `{}` 로 주면 안 된다. 실제 서버는
> null 을 준다. `{}` 를 주면 페이지의 `{d && …}` 가드를 통과한 뒤 없는 필드를 읽어서
> 터지고, 실제로는 나지 않는 오류가 34건 잡힌다(처음에 그렇게 나왔다).

## 별건: 본사 계정이 `/enterprise/hq` 를 못 연다 (미해결)

게이트가 두 개인데 서로 다른 테이블을 본다.

- `/enterprise/*` 대부분 → `get_my_enterprise_role()` → `enterprise_accounts.auth_user_id`
- `/enterprise/hq` → `get_my_franchise_admin()` → **`franchise_admins` 행**

테스트용 본사 계정(`demohq@deudda.com`)은 앞쪽만 만족한다. 운영 DB 에서 확인:

```
get_my_enterprise_role()   → is_hq = true, "Deudda 데모 본사"
get_my_franchise_admin()   → is_franchise_admin = false
```

기기에서 이 화면을 테스트하려면 `franchise_admins` 에 행을 하나 넣어야 한다.
